# Core Trial Set Guide

OpenSVBench currently ranks systems on 26 core trial sets. This document
explains where each trial set comes from and whether its pair list is an
upstream protocol or a protocol built by OpenSVBench.

## Trial file format

Each prepared trial file is a whitespace-separated text file with three or four
columns:

```text
utt1 utt2 label [condition]
```

- `utt1` and `utt2` are utterance IDs from the prepared manifests.
- `label` is `target` for the same-speaker class or `nontarget` for the
  different-speaker class.
- `condition` is optional. When present, it identifies a subgroup used for
  condition-level reporting.

An official dataset split does not necessarily mean that the trial pairs are an
official protocol. For example, GSC uses the official testing split, but its
speaker-verification pairs are generated by this kit. The table below makes
that distinction explicit.

## Interpreting the protocol labels

- **Official protocol** means the pair list is taken from the upstream
  evaluation protocol.
- **Official protocol subset** means the source pair list is official, but this
  kit filters it into a named OpenSVBench condition.
- **Official keys + constructed completion** means upstream labeled keys are
  retained and completed with a deterministic OpenSVBench procedure.
- **OpenSVBench canonical protocol** means the exact utterance manifest and trial
  file are committed in this kit and must be used verbatim.
- **Self-constructed** means the data comes from a public or official split,
  but the speaker-verification pair list is generated by OpenSVBench.

For dataset access, licensing, and citation requirements, see
`DATASET_ACCESS_MATRIX.md` and the dataset notes under `test_prepare_dataset/`.

The short-audio manifests hash decoded mono signed 16-bit PCM samples rather
than WAV container bytes. This keeps the evaluated waveform fixed without
depending on file-header differences between audio-library versions.

The canonical GSC manifest and trial fingerprint are documented in
`resources/canonical/gsc/README.md`. The previous random GSC preparation path is
available only with `--legacy-random true` and is not a core protocol.
